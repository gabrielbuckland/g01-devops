== Deployment Setup

=== 1. Jib Plugin zum `pom.xml` hinzufügen

[source,xml]
----
<plugin>
    <groupId>com.google.cloud.tools</groupId>
    <artifactId>jib-maven-plugin</artifactId>
    <version>3.4.6</version>
    <configuration>
        <to>
            <image>cr.gitlab.switch.ch/hslu/edu/bachelor-computer-science/devops/25hs01/g01/g01-form</image>
        </to>
    </configuration>
</plugin>
----

NOTE: Den Image-Tag enthält die Container-Registry-URL und den Image-Namen des Docker-Images.

=== 2. Docker zur CI/CD Pipeline hinzufügen

Fügen Sie eine GitLab CI/CD-Pipeline-Definition hinzu, die das Docker-Image erstellt und mithilfe des Jib-Plugins in die Registry hochlädt.

[source,yaml]
----
docker:
  stage: build
  image: maven:3.9-eclipse-temurin-21
  rules:
    # run for branches and tags
    - if: $CI_COMMIT_BRANCH
    - if: $CI_COMMIT_TAG
  script:
    # decide tags: commit sha always; add 'latest' on default branch; add tag name on releases
    - |
      TAGS="$CI_COMMIT_SHA"
      if [ "$CI_COMMIT_BRANCH" = "$CI_DEFAULT_BRANCH" ]; then
        TAGS="$TAGS,latest"
      fi
      if [ -n "$CI_COMMIT_TAG" ]; then
        TAGS="$TAGS,$CI_COMMIT_TAG"
      fi

      echo "Pushing to: $CI_REGISTRY_IMAGE with tags: $TAGS"

      # Build & push. Pass auth via system properties.
      mvn compile -B -DskipTests \
        jib:build \
        -Djib.to.image="$CI_REGISTRY_IMAGE" \
        -Djib.to.tags="$TAGS" \
        -Djib.to.auth.username="$CI_REGISTRY_USER" \
        -Djib.to.auth.password="$CI_REGISTRY_PASSWORD"
----

Fügen Sie dies in die `.gitlab-ci.yml`-Datei im Stammverzeichnis Ihres Repositorys ein.

=== 3. Produktions-Docker-Compose Datei erstellen

Erstelle das `docker_prod.yml` File, welches folgendes enthählt:

 * Ein `postgres` Service.
 * Der Anwendungsdienst welcher das erstellte Docker-Image nutzt.

[source,yaml]
----
version: "3.8"

networks:
  backend:
    driver: bridge
    internal: true
  public:
    driver: bridge

volumes:
  postgres_data:

services:
  postgres:
    image: postgres:16
    restart: unless-stopped
    networks: [backend]
    environment:
      POSTGRES_USER: ${POSTGRES_USER}
      POSTGRES_PASSWORD: ${POSTGRES_PASSWORD}
      POSTGRES_DB: ${POSTGRES_DB}
    volumes:
      - postgres_data:/var/lib/postgresql/data
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U ${POSTGRES_USER} -d ${POSTGRES_DB}"]
      interval: 10s
      timeout: 5s
      retries: 5
      start_period: 20s

  app:
    image: cr.gitlab.switch.ch/hslu/edu/bachelor-computer-science/devops/25hs01/g01/g01-form:latest
    restart: unless-stopped
    depends_on:
      postgres:
        condition: service_healthy
    networks:
      - backend
      - public
    environment:
      JDBC_URL: jdbc:postgresql://postgres:5432/${POSTGRES_DB}
      DB_USER: ${POSTGRES_USER}
      DB_PASS: ${POSTGRES_PASSWORD}
      MICRONAUT_ENVIRONMENTS: prod
      JAVA_OPTS: ${JAVA_OPTS:-"-XX:+ExitOnOutOfMemoryError -XX:MaxRAMPercentage=75"}
    ports:
      - "8080:8080"
    healthcheck:
      test: ["CMD-SHELL", "curl -fsS http://localhost:8080/health || exit 1"]
      interval: 15s
      timeout: 5s
      retries: 10
      start_period: 30s
    read_only: true
    tmpfs:
      - /tmp
----


=== 4. Erstelle ein `.env` File

Erstelle ein `.env` File, um die Umgebungsvariablen für das Docker Compose Setup zu speichern

[source,bash]
----
# Postgres
POSTGRES_USER=postgres
POSTGRES_PASSWORD=postgres
POSTGRES_DB=postgres
JDBC_URL=jdbc:postgresql://postgres:5432/${POSTGRES_DB}
----

IMPORTANT: Ersetze die Werte mit sicheren Credentials.
